# MetroViz 实施任务与验收计划

## 1 开发路径

先统一指标和数据状态，再调整布局与图表。现有 CityAssetPreview、城市索引、年份对齐、Hash 路由及降级机制可以复用；不必整体重写前端或更换图表库。

当前技术基线为 React 18、TypeScript、Vite 和 ECharts，数据通过 pipeline 生成静态 JSON。将共享查询状态与格式化封装到 hooks 和适配层，避免 Dashboard、Cities 和 Compare 各自判断日客流是否为零。

## 3 排期与负责人建议

以下是单名熟悉项目的前端工程师、有数据与设计支持条件下的粗估，不是承诺。数据源核验时长取决于能否取得明确口径，不包含在前端工时中。

| 阶段 | 建议工作量 | 完成门槛 |
| --- | --- | --- |
| A 口径和设计冻结 | 产品设计 2 至 3 人日 | 首屏、指标、缺失和比较规则评审通过 |
| B 数据适配和通用组件 | 前端 3 至 4 人日，数据 2 至 4 人日 | 不改原始数据即可产生一致视图模型 |

## 5 测试策略和性能目标

单元测试只覆盖高风险规则：缺失与真实零、年份对齐、比率分母、可比性、URL 去重截断和日期语义。浏览器测试覆盖查城到对标、来源复制、无数据城市和移动端。既有断言因产品行为改变需要更新时，须用对应的新 AC 替代，不能单纯删除来让测试通过。

沿用现有 lint、typecheck、test:unit、check:static、test:ui 和数据 validate 命令。构建回归检查同样需要运行，但本次实施的实际验证结果见 07-implementation-report.md；仍需区分本地检查、实机验收和线上发布。

建议性能验收：在团队约定的中端设备和网络条件下，P0 首页可操作时间不劣于现有二维版本；城市筛选至结果更新 P95 小于 200ms。首次可用时间必须实测并记录环境；尚无实测基线时不宣称已达标。默认二维不加载 echarts-gl；用户启用三维时按需加载，图片和图集资源按需加载。

## 6 结果度量

拟记录 view_ready、city_open、metric_change、compare_start、source_open、copy_success、export_success、data_error。公共属性为页面、指标、期间类型、所选城市数量、视图模式与构建版本。仅记录必要的产品行为，不记录输入框自由文本或用户身份；真实分析服务接入另行配置。

任务完成率定义为进入城市或对标页后成功读取目标指标并完成来源展开或引用操作的会话占比；该代理指标需与用户任务测试共同解释。先记录旧版基线，发布后观察至少两个完整使用周期再做判断。

## 7 发布与回滚

发布前留存现有代码与数据版本。先在预览环境核对关键页面和固定样本，再由项目维护者按现有发布流程上线。正式站数据说明显示 buildCommit、dataVersion 和 collectedAt，便于发现代码与线上错位。

若出现白屏、数据错位、旧链接失效或误导性统计，回退到前一通过验收的构建；元数据 schema 采用新增方式，确保旧版仍能读取原始文件。不能将清空数据当作回滚。

## 8 可直接使用的首批开发任务

第一张任务卡为 DEV-01 和 DEV-02：新增标准指标模型和元数据，替换年度数据依赖日快照的筛选逻辑，补杭州、厦门和福州回归样本，不改变原始数值。完成后交付适配器、schema 和 AC-01 至 AC-04 结果。

第二张任务卡为 DEV-03 和 DEV-04：按本规范调整 tokens 与设计契约，首页改为紧凑上下文加二维 / 三维地图列表，保留旧路由。完成后以 1440×900 和 375px 验收首屏、选择联动与地图失败降级。

第三张任务卡为 DEV-05 和 DEV-06：城市档案与对比篮贯通，对标改为分指标视图，实施可比性门槛与未知状态。完成后提交 AC-07 至 AC-10 录屏或测试结果。
