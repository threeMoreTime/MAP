# MetroViz 视觉与组件规范

## 1 视觉方向

采用城市交通研究工具的视觉语言。浅色画布承载密集资料，深墨色保障阅读，蓝绿色用于主要操作与当前关注对象。交通语义来自清晰导向、城市编号、线路图与连续任务结构，不依赖轨道装饰、立体地图或发光效果。

现有纸墨方案可保留温和背景、低装饰和留白节奏。将宋体从数据数字和主要控件中移出，品牌或说明性标题可少量保留。优先采用系统无衬线中文字体，数字使用等宽数字特性，避免数字变化造成跳动。

本章提出替换性视觉规范。实施时同步修订 `frontend/DESIGN.md` 与 `tokens.css`，不能继续保留“仅允许朱砂强调”和“全屏夜墨 Hero 必须存在”等相冲突的约束。保留原文版本以便回溯。

## 2 色彩角色

| 语义令牌 | 建议浅色值 | 用途 |
| --- | --- | --- |
| canvas | #F4F6F5 | 页面背景 |
| surface | #FFFFFF | 表格、图表和面板背景 |
| text-primary | #182A2F | 主文字、数值 |
| text-secondary | #53676D | 标签和解释 |
| border | #D9E2E2 | 分隔、输入边界 |
| action | #146A73 | 主要操作、焦点和选中城市 |
| selection-surface | #E7F2F1 | 浅色选中背景 |
| source-pending | #8A5900 | 口径待核验提示 |
| error | #B33736 | 加载失败、无效输入 |

上涨与下跌使用箭头和正负号，不用红绿暗示优劣。数据缺失用文字与空心标记；选中态用明确描边与标签。图表比较时固定城市系列映射，依次使用蓝绿、靛蓝、橙棕、紫和灰；必须同时有城市名或线型，不能只凭颜色区分。

验收以实际前景和背景对比为准，正文达到 4.5:1，大字号达到 3:1；重要边界与状态标记达到 3:1。上表是实施起点，实际字号、透明度和叠层改变后须重测。P0 只交付浅色主题，避免同时维护多套未经验证的图表配色。

## 3 排版与密度

| 对象 | 桌面建议 | 移动建议 |
| --- | --- | --- |
| 页面标题 | 28px，600 字重 | 22px，600 字重 |
| 区块标题 | 18px，600 字重 | 17px，600 字重 |
| 正文和表格 | 14px，行高 1.6 | 14 至 16px，行高 1.6 |
| 辅助说明 | 12px，行高 1.5 | 不小于 12px |
| 主数据 | 28 至 32px，tabular-nums | 24 至 28px |
| 控件与触控 | 桌面高度 36 至 40px | 有效触控目标至少 44px |

内容容器最大宽度建议 1360px。桌面左右留白 32px，平板 24px，移动 16px。组件内部采用 8、12、16、24px 节奏，区块间 24 或 32px。主要结果占据首屏，不通过缩小文字塞入过多指标。

圆角统一为 6 至 8px。普通容器采用边界或背景区分，不叠加厚阴影。移除 Emoji 作为主要业务图标，采用现有项目可用的一致线性图标或纯文字。禁止在业务流程显示构建框架、文件路径等实现信息。

## 4 组件契约

MetricContextBar 显示指标、期间、有效样本和采集日。它位于图表之前，并随筛选同步更新。

MetricValue 接收 value、unit、availability、period 和 sourceStatus。数值为 null 时输出破折号和可读原因，禁止格式化为 0、NaN 或 Infinity。

CityRow 使用固定对齐列，城市名左对齐，数值右对齐。加入对标与打开档案是独立操作。选中行保持城市名称和数值可读，不整行反白。

CompareTray 显示已选城市及移除按钮。最小屏幕可换行，进入对标始终可达；不遮盖页面底部内容。已有五城时禁用新增并解释限制。

SourceSheet 显示指标与来源对应关系。桌面可侧栏展示，移动端使用全屏对话框；具有标题、关闭按钮、焦点约束和 Esc 返回。

AvailabilityBadge 区分有记录、缺失、期间未确认和待核验。资料收录徽标与这些状态分组展示，避免用“优秀”“健康”等词描述数据质量。

## 5 图表选择与禁止事项

| 问题 | 默认表达 | 必须包含 |
| --- | --- | --- |
| 城市空间分布 | 二维气泡地图 | 指标、单位、气泡面积图例、缺失图例 |
| 城市规模差异 | 横向条形图或点图 | 零基线、城市名、数值、样本范围 |
| 年度变化 | 折线图与原始数据表 | 年份、单位、缺失断点、期间状态 |
| 两城差异 | 并排数值或哑铃图 | 同期校验、基准定义、原值 |
| 资料覆盖 | 分类计数和可检索清单 | 可用数量及分母 |

不使用综合实力雷达图、不用 3D 柱体表达精确数值、不将不同量纲堆到同一坐标轴、不用饼图比较几十个城市。客流强度与规模分别展示。默认同屏趋势最多五城，其余通过选择管理，避免八条相近墨色折线难以识别。

条形从零开始；趋势轴可适当收紧但必须显示刻度和单位。动画只用于选中反馈或数据切换，建议 150 至 250ms；不自动旋转，不持续闪烁。遵守 reduced-motion，不影响必要信息显示。

## 6 响应式和输出

宽屏为地图与列表并排，城市详情为趋势主区和来源辅助区。中屏上下排列，移动端先列表再摘要，图表可以切换为等价数据表。表格固定城市或指标标签，横向滚动只发生在必要表格内部。

图表图片导出必须包含指标、期间、样本、单位、来源状态和采集日。分享链接保留指标与城市状态，不包含私人身份信息。所有边界状态必须提供设计稿或组件样例，不能只验收有数据的理想页面。

## 7 三维与动效规范

采用有业务含义的局部三维，不恢复全屏宣传 Hero。二维 / 三维共用指标、期间、城市选择和图例。节点不编码不明口径的跨城关系；地理高度固定。三维只在用户启用时加载，浏览器不可用时回退二维。

动效限于焦点移动、选中反馈、内容进入和数据图表更新。交互 120–180ms、内容 220ms、图表或镜头 300–450ms；禁止自动巡航、无限粒子和数值滚动计数。系统减少动态效果与站内开关任一启用即取消动画。
